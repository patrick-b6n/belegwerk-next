# i18n & formatting

The UI is German only, yet **all** UI texts go through
[Paraglide JS](https://paraglidejs.com). Numbers, amounts and dates are
formatted via `Intl` with `de-DE`.

## Convention: no hard-coded UI strings

- Every text that users see or that is read out to them lives in
  [`messages/de.json`](../messages/de.json) – including `aria-label`, `title`,
  `placeholder`, `sr-only` texts, toasts, error messages and the document
  title. This also applies to the generated shadcn/ui components under
  `src/ui/components/ui` (replace English texts after a `shadcn add`).
- Components use texts only through the generated message functions:

  ```tsx
  import { m } from "@/paraglide/messages.js";

  <h1>{m.bookings_title()}</h1>;
  ```

- Keys are `snake_case` and prefixed with their area, e.g.
  `bookings_title`, `bookings_form_amount_label`. Generally reusable texts get
  the prefix `common_` (e.g. `common_close`).
- Parameters instead of string concatenation: `"bookings_count": "{count} Buchungen"` →
  `m.bookings_count({ count })`.
- Not translated: CSS classes, `data-*` attributes, log/error texts for
  developers (e.g. `throw new Error(...)`) and domain values from the
  database.
- Business code does not return finished UI texts but codes (e.g.
  `ParseAmountError`); the UI maps them to messages.
- **EÜR:** The official line labels of the Anlage EÜR (e.g. „Aufwendungen für
  Telekommunikation (z. B. Telefon, Internet)“) are form data like the line
  numbers and come from `src/business/euer/line-mapping.ts`. The display
  names of the positions are UI texts (`euer_position_*`, `euerPositionName`
  in `src/ui/euer`), see [Data model](data-model.md#eür-positions-13).

## Setup

| File                                 | Purpose                                                          |
| ------------------------------------ | ---------------------------------------------------------------- |
| `messages/de.json`                   | All texts (single locale `de`)                                   |
| `project.inlang/settings.json`       | inlang project: locales, message format plugin                   |
| `project.inlang/paraglide.config.js` | Compiler options, shared by the Vite plugin and the CLI          |
| `src/paraglide/`                     | Generated (git-ignored), do not edit                             |
| `project.inlang/cache/`              | Build cache of the Vite plugin (git-ignored, has absolute paths) |

- `pnpm dev` / `pnpm build` compile the messages via the Vite plugin. All
  compiler options (including `outdir`) live only in
  `project.inlang/paraglide.config.js`; `vite.config.ts` only passes
  `project`.
- `pnpm typecheck` runs `pnpm i18n:compile` first, so `tsc` finds the
  generated types in a fresh checkout too.
- The message format plugin is loaded as a devDependency from `node_modules`
  (not from a CDN), so builds run offline and reproducibly.
- The locale strategy is `baseLocale` only; there is no URL/cookie detection.

## Format helpers

Pure functions in `src/business/format` (no React/Tauri), usable from UI and
business code (e.g. for the CSV export):

| Function                   | Example                                                                    |
| -------------------------- | -------------------------------------------------------------------------- |
| `formatCurrency(cents)`    | `123456` → `"1.234,56 €"` (non-breaking space U+00A0)                      |
| `formatAmountPlain(cents)` | `123456` → `"1234,56"` (no thousands separator and no `€`; CSV, #24)       |
| `formatDate(isoDate)`      | `"2025-03-07"` → `"07.03.2025"`                                            |
| `parseAmount(input)`       | `"1.234,56"` → `{ ok: true, cents: 123456 }`                               |
| `parseIsoDate(isoDate)`    | `"2025-03-07"` → `{ year: 2025, month: 3, day: 7 }`, otherwise `undefined` |

Amounts are always integer cents. `parseAmount` works on the digit string
only (no floats), never rounds and returns an error code for invalid input:
`empty`, `negative`, `tooManyDecimals`, `tooLarge`, `invalid`. `tooLarge`
means above `MAX_AMOUNT_CENTS` (100,000,000.00 €, see
[Architecture](architecture.md#booking-service-14)). Whitespace is allowed
only at the edges and next to `€`, not inside the number (`"1 234,56"` is
invalid). The dot is always the thousands separator: `"1.500"` yields
1,500 €. Input fields should therefore show a preview of the recognised
amount.

`formatDate` deliberately takes only ISO calendar dates (`YYYY-MM-DD`), not a
`Date`: that way the result does not depend on the machine's time zone. The
tests run in a non-UTC time zone (`vitest.config.ts`) so time zone bugs show
up on UTC runners too.

Details and edge cases are in the JSDoc comments and tests.
